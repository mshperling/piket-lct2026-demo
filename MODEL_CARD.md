# Карточка модели ПИКЕТ

## Назначение

Приоритизация проверки групп дымовых датчиков по историческим журналам состояний. Прогноз формируется в конце дня D. Целевое окно начала инцидента: D+2…D+15, упреждение больше 24 часов.

Результат представляет оценку диагностического риска. Это не подтверждение пожара или физического отказа. Уверенность в физической причине требует данных осмотров и ремонтов.

## Данные и цель

История 2024–2026 годов, 135 261 069 исходных строк, включая один повторный заголовок. После удаления числовых показаний и повторного заголовка остаётся 25 678 884 дискретных состояния. Витрина содержит 26 групп.

Инцидент определяется по скользящему окну 10 минут: не менее трёх каналов и не менее 10% каналов группы. Серии разделяет промежуток 24 часа без квалифицирующего всплеска. Каталог `sliding` формируется в `ml/incidents.py`.

## Первый ансамбль

Восемь базовых алгоритмов: исходный LightGBM с прежней целью, LightGBM с onset-целью, расширенный LightGBM, LightGBM на недавней истории, LightGBM с новыми признаками, CatBoost Ordered, Extra Trees и логистическая регрессия. Все получают прогнозы на следующих месяцах при одинаковой схеме переобучения.

Сравнивались среднее восьми ответов и две CatBoost meta-модели. Meta-модели получают только OOF-ответы. Расширенный meta-контекст включает историю повторяемости и признаки событий. На разработочном периоде CatBoost meta уступил усреднению.

## Расширенный поиск

Пайплайн `ml/renewal_ensemble.py` добавляет десять алгоритмов к восьми сохранённым OOF-моделям. Максимальный набор содержит 238 признаков. Варианты включают разные глубины деревьев, недавнюю историю, веса по инцидентам, DART и CatBoost глубины 3 и 5.

Признаки повторяемости используют только начала инцидентов, наблюдаемые к концу дня D. История содержит возраст последнего события, интервалы за 3/5/12 прошлых повторов, число событий за 7/30/90/180/365 дней, фазу цикла и условную вероятность следующего повтора. Последняя сглаживает прошлые интервалы нормальными ядрами ширины 7/14/21 день и сжимает оценку множителем n/(n+3).

## Валидация

- Первые OOF-месяцы: май 2024. Последний: июнь 2026.
- Каждая обучающая метка полностью созревает до следующего периода: `max(train.d) + 15 days < prediction.d`.
- Разработка: три квартала с апреля по декабрь 2025, 33 инцидента.
- Проверка: январь–июнь 2026, 22 инцидента.
- Порог выбирается на прошлом калибровочном участке при лимите заявок относительно baseline.
- Выбор первого ансамбля: максимальный событийный F1 на разработке при числе заявок не выше baseline.
- Граф совместных сбоев исключён, поскольку дата его построения позже первых OOF-месяцев.
- Каждая заявка сопоставляется максимум одному инциденту, каждый инцидент максимум одной заявке. Окна с незавершившимся горизонтом исключаются.

Проверяемые периоды уже использовались в исследованиях. Они не являются новым независимым скрытым тестом. Между разработкой и проверкой cooldown начинается заново, что ограничивает прямое сравнение с непрерывной эксплуатацией.

## Воспроизведение

Python 3.12. Основные зависимости находятся в `requirements-research.txt`. Исходные архивы предоставляются организатором отдельно.

```sh
python -m pip install -r requirements-research.txt
python -m ml.temporal_stack --data data/reconstructed_2024_2026 --out models/experiments/temporal_stack_reproduction
python -m ml.renewal_ensemble --data data/reconstructed_2024_2026 --previous models/experiments/temporal_stack_reproduction --out models/experiments/renewal_reproduction
python -m pytest -q
```

Каждый эксперимент сохраняет протокол, OOF-прогнозы, происхождение обучающих выборок, параметры порогов и отчёт. Для нового запуска используется новый выходной каталог. Воспроизведение требует подготовленной витрины с приватными журналами.

## Ограничения и внедрение

Мало инцидентов, короткая история с 2024 года, неизвестная стоимость ложного выезда и пропуска. Дневные признаки не подтверждают причинно-следственные связи. Публичный интерфейс показывает настоящий архивный срез на 29.03.2026 с прогнозами ансамбля восьми моделей. Предложенные черновики не являются журналом состоявшихся выездов. Решения хранятся локально в браузере. Исследовательский ансамбль не заменил текущий пакет `models/production.json`.

Следующий этап: фиксированный период без подбора по его результатам, интеграция ежемесячного переобучения и проверка идентичности признаков офлайн и в API. Результаты осмотров должны дать независимую цель физического отказа.

## Завершённое расширение: 18 моделей

Дополнительные исследования на том же ретроспективном периоде:

| Режим | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| Среднее 18 моделей | 11 | 13 | 11 | 0,4583 | 0,5000 | 0,4783 |
| Политика повторяемости | 10 | 8 | 12 | 0,5556 | 0,4545 | 0,5000 |

Расширенный ансамбль увеличил число найденных инцидентов с 9 до 11, одновременно увеличив число ложных заявок с 7 до 13 относительно ансамбля восьми моделей. Политика повторяемости представляет отдельный кандидат. Эти режимы нельзя описывать общей парой «56,3% точность / 50% полнота».

Источники: `models/experiments/renewal_ensemble_20260929/report.json`, `models/experiments/renewal_policy_20260929/report.json`. Проверка устойчивого пересечения порога в `signal_policy_20260929/report.json` не улучшила выбранный ансамбль 18 моделей: те же 11 TP и 13 FP. Все исследования относятся к уже изучавшимся датам.
